# Deep Review of Menzil Project (2026-10-04)

**Context:** A comprehensive "her cihetten" (all-aspects) review of the `menzil` codebase, specifications, open decisions, and recorded gaps.
**Target Audience:** Project Owner / Core Maintainer.

This review synthesizes the current state of Phase 1 implementation, highlighting critical missing pieces ("eksik gedik"), security vulnerabilities, architectural blockers, and implementation flaws that need to be addressed before a stable MVP release.

---

## 1. Architectural Blockers & TOBEDECIDED Resolutions

These items actively block the completion of L4 (specifically `L4e` and `L4h`) and must be resolved immediately.

### 1.1 The L4 Re-handshake Identity Problem (TOBEDECIDED #6)
- **The Flaw:** `protocol.md §5.2` mandates a full re-handshake every 24 hours without dropping active L5 streams. However, the `init` record (Noise message 1) carries *no payload* by design (`protocol.md §5.1`). A responder cannot distinguish between a scheduled re-handshake of an existing session and a completely fresh start from a peer that lost its state (e.g., restarted).
- **Impact:** Blocks `L4e` (session table) and `L4h6`/`L4h8` (handshake orchestration).
- **Proposed Fix:** Modify the spec. The identifying marker must go into `resp` (Noise message 2), the prologue, or a dedicated control record *after* the handshake. Relying on `init` is cryptographically impossible under current strict-decode rules.

### 1.2 Pluggable Policy Evaluation (TOBEDECIDED #7)
- **The Flaw:** `menzil-node::PolicyStore` hardcodes evaluation against the native `Policy` document. `ng_sdwan` (the first enterprise consumer) requires a pluggable `PolicySource` trait to integrate with its organizational profiles.
- **Impact:** Restricts adoption for enterprise SASE architectures.
- **Proposed Fix:** Extract the evaluation logic in `L4h2` / `L4h4` behind an async `PolicyProvider` trait before finalizing the `open_stream` API.

### 1.3 Personal vs. Multi-Tenant Name Claiming (TOBEDECIDED #1)
- **The Flaw:** `LabelRegistry::clear_for` immediately releases a claimed name when a session ends or reconnects. In a multi-tenant environment, a network blip allows a different node to snipe a freshly-freed name. 
- **Impact:** Name hijacking in shared environments.
- **Proposed Fix:** Implement a grace period (e.g., 5 minutes) for label re-claiming tied to the `NodeId` before returning it to the general pool.

## 2. Security & Threat Model Gaps

Several "accepted" or deferred gaps actively violate `protocol.md` and the threat model.

### 2.1 State Persistence and Downgrade Attacks
- **The Flaw:** `NodeHistory` (L3) and `L4` peer states are entirely in-memory. `protocol.md §2.2` states verifiers must "reject a lower serial than the highest they have accepted". Because this state drops on restart, a restarted node/relay is vulnerable to replay attacks and NodeCert downgrade attacks.
- **Action:** A persistent high-water mark store (key-value or write-ahead log) must be introduced for `min_serial` and TAI64N timestamps.

### 2.2 Steward Signatures Rejected
- **The Flaw:** `RosterStore` currently rejects any `Roster` signed by a Steward. 
- **Impact:** Breaks `protocol.md §2.3` and §7.3. Since documents expire in 14 days, the network will automatically fail closed because the automated steward renewals will be rejected by the nodes.
- **Action:** `RosterStore` must be updated to accept steward signatures against the `stewards` list of the previously accepted Roster.

### 2.3 OPEN `meta` Spoofing
- **The Flaw:** `menzil-stream` passes `meta` (containing `client_ip` and `sni`) verbatim to the target node. A malicious member can forge these values.
- **Impact:** Target nodes relying on IP allow-lists (via `ServiceHandler`) can be bypassed.
- **Action:** `L4h4` MUST strip or overwrite `meta` with `OpenMeta::default()` for all member-initiated streams. `meta` should only be trusted if the initiator is verified as the relay principal.

### 2.4 WELCOME Network Enumeration Leak
- **The Flaw:** The relay sends `WELCOME` unconditionally upon completing the Noise IK/XX handshake, listing *every* network the relay serves in `rosters.seqs()`, before the client's `HELLO` is validated.
- **Impact:** Allows unauthenticated scanners to enumerate all networks hosted on a relay.
- **Action:** Defer sending the full network list until `HELLO` is authenticated, or only return the sequences for the networks the node explicitly claimed in `HELLO`.

## 3. Availability and DoS Vectors (Resource Exhaustion)

### 3.1 Relay Connection & Handshake Floods
- **The Flaw:** `Relay::serve` spawns tasks per connection with no concurrency limits. `protocol.md §10` specifies limits (60 HELLOs/min per IP, 10 per NodeId), but they are unbuilt.
- **Impact:** A trivial TCP or Noise handshake flood will exhaust relay memory/CPU.
- **Action:** Implement a connection manager with a semaphore and token-bucket IP rate limiting before the Noise state machine is allocated.

### 3.2 L4 Outbound Frame Budget Fail-Fast
- **The Flaw:** `menzil-stream` has a 256-frame outbound budget that fails the *entire* session if exceeded. A burst of 129 refused `OPEN` requests from a peer (costing an `OPEN_ACK` and `RST` each) triggers this.
- **Impact:** A single hostile or misconfigured peer can kill the relay's session to the node.
- **Action:** Replace the fail-fast error with backpressure (`Poll::Pending`), or implement strict admission pacing in `L4h4`.

### 3.3 Yamux Receive Window Explosion
- **The Flaw:** Yamux 0.14.1 lacks per-stream limits. A single stream can auto-tune up to 48 MiB.
- **Impact:** A fast sender on a single stream can exhaust the relay's 4 MiB L3 per-destination queue, causing `credit_exceeded` and killing the entire L4 session for all other streams.
- **Action:** `L4h5` must enforce a global per-session byte accounting wrapper over the yamux instance.

### 3.4 DOC Propagation Memory Leak
- **The Flaw:** `DocReassembler` has no eviction for abandoned or incomplete transfers. Furthermore, DOC fan-out drops chunks silently if the outbound queue is full.
- **Impact:** Memory leaks over time on the relay; members silently fail to receive Roster updates.
- **Action:** Add a timeout-based eviction to `DocReassembler`.

## 4. Implementation Bugs & Flaws

- **`RosterStore::min_serial_for` Bug (`menzil-relay`):** Currently returns the *first* matching entry for a NodeId instead of the maximum `min_serial`. A stale duplicate entry can bypass revocation/upgrade logic.
- **`live_session.rs` Flake:** The test fails ~50% of the time under load because `wait_until_routable` probes queue up and arrive in a burst, overtaking the actual payload. The test harness needs to filter probe payloads or use a dedicated prober identity.
- **`E2eInitiatorHandshake::finish` Consumes Self:** If `resp` fails to decrypt, the state machine drops `self`. An attacker injecting a single forged message forces the initiator to drop a legitimate handshake and start over.
- **Yamux Reset Gap:** `yamux::Stream` cannot be force-reset after a half-close. `protocol.md §5.2` requires abrupt resets on abnormal ends. A newtype wrapper is needed to manually emit `RST`.
- **Revoked Member Roster Push:** `catch_up_targets` pushes new Rosters to all attached sessions that claimed the network, *without* checking if that session's NodeId is revoked in the very Roster being pushed.

## 5. Missing Features (Phase 1 & Phase 2 Checklist)

### Immediate Phase 1 Pipeline (`TODO.md L4h` & beyond)
1. **L4h1-L4h8:** The core node engine wiring is completely pending. `open_stream` does not exist yet.
2. **L4i:** Dispatching `OPEN` to local `tcp:`/`http:`/`tls:` targets.
3. **L4j:** `menzil:docs` end-to-end service (critical for the 14-day expiry lifecycle).
4. **L4k:** Live grant re-evaluation (terminating streams when a Policy update revokes them).
5. **Agent & IPC:** Local Unix Domain Socket / Named Pipe agent for CLI `stdio` and `reach`.
6. **Relay ACME (`expose`):** Terminated mode with Let's Encrypt integration.

### Phase 2 Pipeline
1. **Datagram Channels (`protocol.md §5.4`):** UDP tunneling over `DGRAM` records.
2. **Egress (S3):** Local SOCKS5 / HTTP CONNECT listener with Policy-based DNS resolution and IP deny-listing.
3. **Quotas & Custom Domains:** DNS TXT verification for custom domains; 90-day quarantine rules.
4. **Blind Shares (Node-side ACME):** TLS-ALPN-01 and HTTP-01 routing.

---

## 6. Executive Summary & Recommended Next Steps

The codebase is exceptionally well-specified and the cryptographical protocol (`menzil-proto`, `menzil-session`, `menzil-e2e`) is solid. However, the system currently suffers from **memory-only state tracking** and **resource exhaustion vulnerabilities** that break the threat model's availability guarantees.

**Immediate Actions:**
1. **Resolve TOBEDECIDED #6:** Update `protocol.md` to add a session identifier to the `resp` payload or the prologue so `L4h8` re-handshakes can be implemented.
2. **Fix the `min_serial_for` bug** in `menzil-relay` to prevent downgrade attacks.
3. **Implement L4h1:** Expose `run_session` properly so the L4 engine can actually send reliable records without silent drops on reconnect.
4. **Fix the `live_session.rs` flake** so CI remains trustworthy before proceeding with the complex `L4h` async wiring.
